# OpenTodo website

The public website of [OpenTodo](https://github.com/pixari/opentodo), the open-source task manager you host yourself. Live at <https://open-todo.app>; the demo runs at <https://demo.open-todo.app>.

The site is built with [Astro](https://astro.build) to static files and served by nginx. Everything it says about the app (version, docs, screenshots, colours, icons, changelog, import formats) comes from the app's **site bundle** of a pinned release, never from files copied by hand. How the site is built and what it must do is specified in `openspec/` (see `AGENTS.md`).

## Run locally

Needs Node 22.

```bash
npm ci
npm run dev        # fetches the pinned bundle into .bundle/, then http://localhost:4321
npm run build      # fetches the bundle, checks the content, builds dist/
npm run serve      # serves dist/ like nginx on http://127.0.0.1:4321
```

## The site bundle

`bundle.json` pins where app facts come from. Exactly one of:

| Pin | Meaning |
| --- | --- |
| `{ "version": "v0.4.0" }` | The release asset `opentodo-site-bundle-v0.4.0.tar.gz` from the app's GitHub releases, checked against the release's `SHA256SUMS`. |
| `{ "preview": "<run id>" }` | The bundle artefact of an app CI run on main (needs `GITHUB_TOKEN`). Every page shows a "Preview" banner, and production builds refuse it. |
| `{ "interim": true }` | **Today.** Assembled from `interim/` by `scripts/interim-bundle.mjs`, because the app does not publish bundles yet (app change `site-bundle`). |

`BUNDLE_DIR=/path/to/bundle npm run build` uses a local bundle folder instead; that is always a preview.

Updating the site to a new release is a one-line change to `bundle.json`. When the first real bundle is pinned, delete `interim/` and `scripts/interim-bundle.mjs`.

The interim bundle holds the docs site (generated by the app's `make docs`), the screenshots, `tokens.css` and the icon sprite extracted once from the app's design-system tokens and Lucide set, a `changelog.json` parsed from the app's `CHANGELOG.md` at v0.3.0, and a hand-written `manifest.json` marked `"interim": true`.

## Checks

| Command | What it fails on |
| --- | --- |
| `npm run build` | A page that does not render; content front matter that breaks its schema (a comparison without `checkedOn` or older than 180 days, an OpenTodo claim without a docs link, a guide or template not reviewed in a year); a paragraph that claims a feature without a docs link (`scripts/check-content.mjs`). |
| `npm run check` | TypeScript and Astro errors. |
| `npm test` | Unit tests of the bundle scripts, template generator, content rules and checks. |
| `npm run check:dist` | Broken internal or docs links and anchors; emoji or symbols used as icons; scripts from origins other than the site and the self-hosted analytics. |
| `npm run test:browser` | Serious or critical axe violations in light and dark at 360 and 1280 px; horizontal scroll; pages that do not read and navigate without JavaScript; broken islands. Needs Playwright's Chromium (`npx playwright install chromium`). |
| `npm run templates:check` | A template that does not import cleanly into a server of the pinned release (`OPENTODO_URL`); also captures each template's screenshots into `src/assets/template-shots/`. |

GitHub Actions runs them on every pull request and on main (`.github/workflows/`).

## Content

| Folder | Pages |
| --- | --- |
| `src/content/compare/` | `/vs/<app>`: honest, dated comparisons |
| `src/content/templates/` | `/templates/<slug>`: a template tree, turned into a downloadable `opentodo-export` file at build time |
| `src/content/guides/`, `toolkit/`, `essays/` | Guides, setup toolkits and essays |
| bundle `changelog.json` | `/whats-new/<version>` and `/feed.xml` |

Content is drafted following `content/VOICE.md`, picked from `content/BACKLOG.md`, and published only through a reviewed pull request.

## Deploy on Coolify

1. **+ New Resource → Public Repository**, `https://github.com/pixari/OpenTodoWebsite`, branch `main`.
2. **Build pack**: Dockerfile. **Base directory**: `/`. **Port**: `80`. No environment variables.
3. Assign the domain `open-todo.app` and deploy.

The Dockerfile builds the site (fetching the pinned bundle) and copies `dist/` into `nginx:1.27-alpine`. Any static host works too: publish `dist/`, serving `index.html` for directory URLs and `404.html` for unknown paths.
